# desktop-and-release

## Pieces

- `src-tauri/` is the Tauri 2 shell (identifier `dev.formai.formencoder`). It starts the sidecar `formencoder-engine`, shows `splash.html` until the engine answers, then loads the interface the sidecar serves.
- `setup/freeze_backend` builds the sidecar with PyInstaller: the service, `fe_core`, the built interface (`frontend_dist`), the agent templates, `.claude/skills`, `backend/app/resources` and `ffmpeg-licence.json`. The binary is named with the target triple in `src-tauri/binaries/`.
- `setup/bundle_ffmpeg.py --target TRIPLE` stages the pinned LGPL FFmpeg into `src-tauri/ffmpeg`, checking every file against `src-tauri/binaries/ffmpeg-licence.json`; without a recorded build the app downloads FFmpeg on first run.
- `setup/desktop_build` runs the three in order and then `tauri build`, passing on any extra arguments (formcompiler's `--config FILE` with the updater settings). `formencoder.bat desktop build` and `setup\desktop_build.bat` pass them on the same way, so Windows builds make updater files too. On macOS it runs `setup/sign_resources.py` before `tauri build`: with `APPLE_SIGNING_IDENTITY` set, every Mach-O file in `src-tauri/tools` and `src-tauri/ffmpeg` is signed with hardened runtime and a timestamp, since Tauri does not sign resources and notarization rejects unsigned code.
- The app icon in `src-tauri/icons/`, `assets/formencoder_icon*.png`, `frontend/public/favicon.png` and the mark in `splash.html` are all generated by `assets/icon_src/`; change the drawing there and regenerate (steps in `frontend/HASHOUT_LOG.md`), never hand-edit one size.
- `./build_app` at the repo root (and `build_app.bat` on Windows) is the one-shot build from a fresh clone, in the family shape formlit set: tool checks and rustup, `install_all`, `install_desktop`, then the desktop_build chain, with a DMG and the copy to Applications on macOS and a `.deb` on Linux. Its Rust helpers are `fe_rust_env` and `fe_rust_fresh` in `setup/lib.sh`. The release workflow keeps calling `./formencoder desktop build`.

## Targets

| OS | Triple | Bundles |
| --- | --- | --- |
| macOS Apple silicon | `aarch64-apple-darwin` | `.app`, `.dmg` |
| macOS Intel | `x86_64-apple-darwin` | `.app`, `.dmg` |
| Windows | `x86_64-pc-windows-msvc` | `.msi`, NSIS `.exe` |
| Linux | `x86_64-unknown-linux-gnu` | `.deb`, `.rpm`, `.AppImage` |

formcompiler (`nodemode-ai/formcompiler`) builds all four when a `compile_vX.Y.Z` branch is pushed here, and the repo's own `ci.yml` builds the interface, checks the engine on each host, runs the text lint and `agents sync --check`.

## Releasing

1. Bump every version file listed in the skillset's Versions rule to the same `v*.*.*`.
2. Update `BUILD_NOTES.md` in the planning sidecar with what changed.
3. Commit `chore(release): vX.Y.Z` last in the series; push a branch `compile_vX.Y.Z` from that commit. formcompiler builds it and drafts `formencoder-vX.Y.Z` on its release page, with the FFmpeg source attached.
4. The FFmpeg notices (`NOTICE.md`, `src-tauri/ffmpeg/README.md`) must ship with every bundle that carries FFmpeg: the LGPL requires the licence text, the source offer and the build's configure line.
